# 2026-10-01 — SOV Station UI preservation checkpoint

## Scope and version

The owner requested a brighter, cleaner native wallet with a Tari-inspired feel,
better sending and privacy layout, and **no omitted existing operations**. They
confirmed the running version is 0.2.13 and pool v2 is live. Existing production
window text confirms 0.2.13; older on-disk bundle metadata is not evidence that
the running process is on that older version.

Source baseline is `29e7a11`, branch `codex/station-next-gen-ui`. The Station
package version is now 0.2.14. A separate native application identifies itself
as **SOV Station PREVIEW**, version **0.2.14-preview**. No release/tag/push or
production app replacement was performed.

## What changed and what remains

- Theme and shell: brighter body/strong text, shared design helpers in
  `node/src/gui/design.rs`, compact workspace navigation, consistent gutters,
  dark/light themes, bounded status footer and scrollable transaction reviews.
- Wallet tasks: Overview, Send, Receive, Privacy, Identity and Backup. Existing
  operation dispatch remains outside the task-specific rendering scopes. The
  mandatory recovery acknowledgement still blocks ordinary wallet controls.
- Overview/Privacy separate public balance from **owned v1 and owned v2** notes;
  unknown/unscanned values are not shown as zero. Network pool totals, drain
  budgets and cryptography remain available in pool details.
- Send retains all original routing, shortcut/Undo, Max, priority tip/live auction,
  review, pending/replacement and offline workflows. Cost display reflects the
  current form values. Watch-only online signing is refused; unsigned-build and
  already-signed broadcast remain accessible.
- Privacy retains v1 scan/rescan/de-shield and explicit private-pool choice,
  plus live v2 scan/private-send/shield/de-shield controls and their existing
  guards. Choosing a pool is explicit; v1/v2 recipients cannot be mixed.
- Pool review subtracts only the note amount from the pool. Its network fee is
  paid by the public account. V2 does not claim the v1 estimate is its exact fee:
  the STARK proof must be built before that fee is known.
- V2 receiving/copy/export shows the connected pool state accurately, including
  Active, Dormant and Unavailable. A long v2 address remains exportable.
- Transaction/replacement reviews expire on changed wallet/account, network,
  current RPC or payment terms. Fee replacements pin the authorized bid and
  original nonce/recipient/amount rather than silently increasing the bid.
- Pending history retains original chain/RPC metadata. Connecting to another
  node on the **same chain** does not hide it or prevent receipt updates/new
  replacement reviews. Another chain cannot settle or replace those entries.
- Assets, Swaps, Vaults, Activity, Node, Mining and Blocks retain their existing
  operation handlers. Node start still starts with mining off; payout identity
  does not falsely imply active mining.

The preservation audit checked 45 operation families. The searchable
[feature map](station-ui-feature-map.md) contains 100 operation/capability rows
with UI locations, handler names and constraints. It distinguishes existing UI
operations from CLI-only or roadmap capabilities. README links point to it.
Stale GUI descriptions were corrected, including the old coinbase split,
largest-note-only de-shielding and a standalone activation button that neither
the baseline nor current GUI implements.

- `cargo test --offline --bin sov-station`: **160 passed, 0 failed, 1 ignored**.
  Includes recovery/task reachability, all workspace destinations, unknown pool
  balances, live-v2 receiving/export copy, v2 guard matrix, source selection,
  cross-pool refusal, review/bid/context preservation, cross-chain outbox
  isolation, same-chain node migration and compact review scrolling.
- `cargo clippy --offline --all-targets -- -D warnings`: clean. Production
  `cargo build --offline --bin sov-station`: succeeds. The separate disabled
  preview also builds; unused-code warnings there come from its action stubs.
- Native inspection of the disposable preview covers dark/light text contrast,
  both owned pool amounts, public send review/cancel, v2 private review/cancel,
  scan feedback, live-v2 receive/export and shield/de-shield/window limits.
- The preview uses throwaway keys and synthetic public/v1/v2 balances; RPC is
  fixed to `127.0.0.1:0`, separate `SOV_STATION_DIR`. Proof generation, signing,
  broadcasting, node launch/mining and wallet persistence are disabled only in
  its generated copy. Its action stubs are not production source changes.
- No real transaction, Halo2/STARK proof, operator-key signing or remote-node
  integration was exercised during UI inspection. These checks do not replace
  normal release/integration gates. Baseline limitations such as the exact v2
  fee being unavailable before proof construction are not claimed solved.
- Running production wallet/node, real wallet material, chain files and genesis
  were left alone. No chain reset or activation change occurred.
