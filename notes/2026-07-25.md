# 2026-07-25 — release version contract hardened

Branch `feat/release-version-contract` (off `d260a76`). CI/release tooling + docs only —
no consensus, no chain crates, no version bump, no tag created or moved.

## Done

- **`scripts/version-contract.sh` (new)** — one implementation of the release rules,
  called by BOTH the developer path and CI so they cannot drift:
  `precut vX.Y.Z` (before a tag exists) and `verify-tag-push vX.Y.Z <sha>` (after the
  tag push, in CI). Enforces: tag == `node/Cargo.toml` (the single version source);
  version never re-used (local tag / remote tag / existing GitHub Release); tag never
  moved (remote tag must still point at this commit); release only from the CURRENT head
  of `origin/main` (head equality — an ancestor is refused, it would omit commits main
  already has). `--require-gh` makes an unanswerable GitHub API fail CLOSED.
- **`scripts/verify-artifact-version.sh` (new)** — the built artifact must PROVE its
  version: `station` (runs `sov-station --version`), `daemon` (boots the freshly built
  `sov-rpcd` on an isolated port and asks `sov_version` over JSON-RPC), `embedded`
  (baked `SOV_VERSION` / `sov/vX.Y.Z` agent literal, and NO `git describe` fallback),
  `plist` (macOS bundle keys), `no-describe` (`sov-testnet`, which has no version
  surface of its own).
- **`node/src/main.rs`** — `sov-station --version|-V|version` prints `sov-station X.Y.Z`
  (`CARGO_PKG_VERSION`, the same number the GUI status bar shows). Unit-tested. This is
  the only code change outside CI/docs; the release check needs an executable surface.
- **`release-gate.sh`** — `--cut` now runs the contract as a FAST pre-flight (before the
  ~30-minute verification surface) and AGAIN immediately before tagging (closes the
  TOCTOU window where main moves or the version gets published mid-run). Nothing
  existing was weakened; `--strict` is still strict.
- **`release.yml`** — `gate` now: requires a TAG ref (no `workflow_dispatch` publishing
  off a branch), keeps the existing version guard, runs `version-contract.sh
  verify-tag-push --require-gh`, and runs the guard test-suite. Every build job
  (windows · macos · linux) asserts the artifact's version BEFORE staging, so a
  mis-versioned binary is never packaged. `fetch-depth: 0` so refusals can name the
  ref's exact relation to main.
- **`ci.yml`** — new `release-contract` job: `shellcheck` over the release scripts +
  `scripts/tests/release-contract.test.sh` on every push.
- **`scripts/tests/release-contract.test.sh` (new)** — 35 cases, every one a REFUSAL
  path, against throwaway git repos with real `file://` remotes, a stubbed `gh`, and
  synthetic binaries. No network, no cargo, seconds to run.
- **`notes/release-version-contract.md` (new)** — the contract as a runbook.

## Version-inconsistency holes found while in there

1. **macOS `CFBundleVersion` was hardcoded `0.1.0`** in `release.yml` — every release
   ever published claimed build version 0.1.0 in Finder. Now the tag; and
   `CFBundleShortVersionString` now uses Apple's numeric form (`0.1.99`, not `v0.1.99`).
   Both asserted by `verify-artifact-version.sh plist`.
2. **`sov-testnet` ships with no version surface** — it links the node library but the
   version constants are optimised out, so it can only be checked for a describe
   fallback. Disclosed, not papered over.
3. **`sov-rpcd` has no `--version` flag** (adding one means touching `chain/crates/rpc`,
   out of scope here) — hence the live-RPC probe, which is a stronger proof anyway.

## Proven, not asserted

Guards demonstrated firing against REAL data, not just fixtures:
`release-gate.sh --cut v0.1.99` on a feature branch → refused (RULE 3);
`precut v0.1.98` on a clone of the real repo → refused, tag already exists (RULE 2);
`verify-tag-push v0.1.98 … --require-gh` against real GitHub → refused, Release exists;
`precut v0.1.98` with the real `origin/main` → refused, commit is an ANCESTOR;
`embedded` on the stale local `sov-rpcd` (baked `v0.1.97-16-g7dce59b`) and `sov-station`
(`v0.1.84-3-g4e50ac3-dirty`) → refused; `daemon` on a freshly built `sov-rpcd`
(`SOV_BUILD_VERSION=v0.1.99`) → `sov_version` answered `v0.1.99` live, and the same
binary claimed as `v0.1.98` → refused.
