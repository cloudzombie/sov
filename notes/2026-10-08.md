# 2026-10-08 — Rust Station quantum hardening and 0.2.15

The owner requested a working post-quantum hardening implementation in the Rust
SOV Station/main client, excluding TypeScript wallet work. The resulting patch
corrects hybrid peer transcript/account binding, closes secondary authorization
retirement paths, preserves imported legacy identity material, adds explicit
reviewed hybrid migration and verifies recipient-bound Orchard recovery.

The current v2 prover's unmasked trace does not establish confidentiality. New
v2 proof creation and broadcast are quarantined in Station and new carriers are
rejected recursively by RPC/gossip. Existing history remains verifiable. These
gates contain the defect; a reviewed versioned replacement proof/hash suite is
still required. Mainnet PQ retirement remains unarmed. The fresh isolated PQ
rehearsal executes rotation, retirement, sunset and cold replay without changing
mainnet genesis or existing deployment schedules.

Before release preparation, 170 active Station tests passed with one intentional
ignore, together with relevant runtime, real Orchard proof/authorization,
network, RPC and replay checks. Formatting and relevant Clippy checks passed.
The updated native client was built and relaunched in the separate disposable
quantum preview; no real-fund transaction or fleet deployment was performed.

The owner then explicitly requested pushing to `main` and cutting new 0.2.15
versions. The Station version source and lock entry are now 0.2.15; a local binary
self-report and its embedded daemon/peer version were verified against v0.2.15.
Release preparation updates the five-node policy checks to assert v2 quarantine
instead of successful creation with the unsafe suite. The ordinary release gate
and platform workflow remain required, with no manual tags or gate bypass.
